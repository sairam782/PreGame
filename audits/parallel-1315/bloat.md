# Bloat audit — code-level duplication/complexity in pregame/ and scripts/

**Verdict.** ~6,500 lines across pregame/+scripts/ is lean for the feature surface; no single file is
egregiously bloated. The one real drift risk is `gate._loss_reason` recomputing what `metrics.compare`
already decided, plus a duplicated `CONTEXT_GROWTH_LIMIT` constant — both flagged in the prompt and
confirmed. A dead `hasattr` branch and a vestigial `importlib`-based lazy-import pattern (14 call sites,
no circular import, no monkeypatch use) are the other concrete findings. Total safely removable now:
~10-15 lines; the bigger duplication (~50 lines) needs a wording/test rewrite, so it should wait.

## Notes / ruled out
- Confirmed by grep: no unused `Settings` fields, no dead `RULE_KEYS`/`GUARDRAIL_KEYS`/`DEFAULT_GUARDRAIL_CHECKS`/`_numbers`/`_gains` — all are called.
- Largest functions (`versions._txn` 109 lines, `gate._evaluate_config_change` 79 lines, `loop.status`/`run_demo` ~87 lines) are the transactional fence and orchestration core — complexity paid for by the project's central claim, not bloat.
- Fake/live forks (drafter, oracle.grade) are a stated design requirement (offline demo, DESIGN.md) — not cuttable without breaking the no-network demo path; earlier audit already noted this in passing, not repeated here in depth.
- No linter (pyflakes/flake8) installed in the venv; relied on targeted grep cross-referencing instead. `pytest --collect-only` succeeded (252 tests collected), confirming the tree is currently healthy for risk assessment.
